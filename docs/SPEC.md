# Questlet — Mac 개인 업무 일정 앱 명세

작성일: 2026-10-01. 최종 수정일: 2026-10-19. Q1~Q32와 이후 명세 수정 요청을 반영한 프로젝트 기준 문서다. 기술은 SwiftUI로 확정했으며, 2026-10-03 사용자가 최종 디자인을 승인했다. SwiftUI 네이티브 구현과 mock 연동을 완료했다. 실제 사내 API 연결은 제외하며 검증 범위는 IMPLEMENTATION.md에 기록한다.

## Problem Statement

사용자는 Jira 작업의 시작일·종료일과 상태를 반복해서 변경하는 일을 번거롭게 느낀다. 이전에 어떤 작업을 어떤 기간으로 등록했는지 기억하기 어렵고, 일정이 조정될 때마다 다시 찾아 수정해야 한다. 제목 요약이나 명확한 날짜 입력까지 느린 사내 AI에 맡기는 것은 이 목적에 맞지 않는다.

## Solution

작업 제목, 선택적인 Jira 티켓 번호, 날짜 범위를 폼으로 입력하는 개인용 Mac 앱을 만든다. 작업과 원문 코멘트는 로컬에 먼저 저장하며, 연결된 Jira 티켓이 있으면 직접 반영 결과까지 기다려 같은 화면에서 성공·실패를 알린다. 메뉴바 팝오버는 진행 중·예정·완료 탭으로 작업을 보여주고, 앱 창은 전체 작업 목록·상세·등록·수정·로컬 키워드 검색을 제공한다.

첫 버전은 emux API 호출, 에이전트 프롬프트, 채팅 UI 없이 동작한다. Jira·emux PAT 입력과 키체인 저장은 사내 연동 준비 기능으로 포함한다. 실제 Jira 호출은 사내 환경에서만 가능하므로 이번 결과물에는 교체 가능한 모의 연동과 실제 연결 지점에 대한 주석을 포함한다. 모의 성공을 실제 Jira 반영 완료로 표시하지 않는다.

## User Stories

1. 개인 사용자로서 작업 제목을 그대로 입력하여, AI 응답을 기다리지 않고 등록하고 싶다.
2. 개인 사용자로서 티켓 번호를 생략하여, Jira와 무관한 작업도 관리하고 싶다.
3. 개인 사용자로서 하나의 달력에서 시작일과 종료일을 선택하여, 기간을 쉽게 입력하고 싶다.
4. 개인 사용자로서 시작일 이전 날짜를 종료일로 선택할 수 없게 하여, 잘못된 기간 입력을 처음부터 방지하고 싶다.
5. 개인 사용자로서 날짜 범위를 모두 선택하기 전에는 저장할 수 없게 하여, 유효한 일정을 등록하고 싶다.
6. 개인 사용자로서 저장 버튼으로 입력을 확정하여, 별도의 AI 확인 대화를 생략하고 싶다.
7. 개인 사용자로서 동일한 티켓을 다시 등록하면 기존 작업을 안내받아, 같은 Jira 일정에 여러 로컬 작업이 충돌하지 않게 하고 싶다.
8. 개인 사용자로서 티켓이 없더라도 같은 제목의 중복 작업은 등록되지 않기를 원한다.
9. 개인 사용자로서 전체 작업을 목록으로 보고, 이전에 등록한 업무를 기억하지 않아도 찾고 싶다.
10. 개인 사용자로서 진행 중·예정·완료 작업을 탭으로 구분해서 보고 싶다.
11. 개인 사용자로서 작업 상세에서 제목·기간·티켓·코멘트·Jira 반영 상태를 확인하고 싶다.
12. 개인 사용자로서 로컬의 제목·티켓·코멘트를 키워드로 검색하여, 네트워크 없이도 기록을 찾고 싶다.
13. 개인 사용자로서 완료된 작업도 검색하여, 일정 연장이나 과거 자료 조회에 활용하고 싶다.
14. 개인 사용자로서 같은 검색어의 여러 결과를 제목·기간·티켓으로 구분하고 싶다.
15. 개인 사용자로서 편집 아이콘으로 제목·티켓·기간을 한 폼에서 수정하여, 빠르게 작업 정보를 조정하고 싶다.
16. 개인 사용자로서 종료일만 연장할 때 시작일은 유지하고 싶다.
17. 개인 사용자로서 변경을 취소하면 저장되지 않도록 하여, 실수로 수정하지 않고 싶다.
18. 개인 사용자로서 날짜에 따라 작업 상태가 자동 변경되도록 하여, 상태를 직접 관리하지 않고 싶다.
19. 개인 사용자로서 종료일 당일에도 진행 중으로 표시되고, 다음 날 완료로 표시되길 원한다.
20. 개인 사용자로서 종료일을 오늘로 수정하면 내일부터 완료 상태가 되길 원한다. 이후 요청에 따라 상시 안내 행은 표시하지 않는다.
21. 개인 사용자로서 완료된 작업의 종료일을 연장하면 상태가 즉시 다시 계산되길 원한다.
22. 개인 사용자로서 메뉴바 팝오버에서 진행 중인 작업을 기본으로 보고, 예정·완료 탭으로도 전환하고 싶다.
23. 개인 사용자로서 팝오버에서 작업 상세·앱 열기·새 작업·작업 수정으로 빠르게 이동하고 싶다.
24. 개인 사용자로서 작업 상세에 원문 코멘트를 직접 추가하여, 대상을 다시 설명하지 않고 기록하고 싶다.
25. 개인 사용자로서 코멘트에 포함된 링크와 기록 시각을 보고, 예전에 저장한 자료를 찾고 싶다.
26. 개인 사용자로서 기록 시각이 실제 자료 수신 시각처럼 표현되지 않기를 원한다.
27. 개인 사용자로서 연결 티켓이 있으면 저장 후 Jira 응답까지 기다려, 결과를 바로 확인하고 싶다.
28. 개인 사용자로서 Jira 반영 중에는 처리 중 표시와 중복 제출 방지를 제공받고 싶다.
29. 개인 사용자로서 Jira 반영 성공·실패를 같은 화면에서 확인하여, 별도 알림을 기다리지 않고 싶다.
30. 개인 사용자로서 Jira 실패에도 로컬 변경은 유지하고, 같은 화면에서 오류를 확인하고 재시도하고 싶다.
31. 개인 사용자로서 앱 창을 닫아도 메뉴바 기능과 백그라운드 반영이 계속되길 원한다.
32. 개인 사용자로서 앱을 완전히 종료했다가 다시 실행해도 미처리 반영 요청이 재개되길 원한다.
33. 개인 사용자로서 연속해서 일정을 바꾸더라도 Jira에 오래된 값이 최종 반영되지 않기를 원한다.
34. 개인 사용자로서 여러 코멘트는 각각 전달되고 재시도로 중복 추가되지 않기를 원한다.
35. 개인 사용자로서 잘못 등록한 작업을 확인 후 로컬에서 삭제하고 싶다.
36. 개인 사용자로서 삭제해도 Jira 티켓은 남는다는 안내를 받고, Jira 처리는 직접 하고 싶다.
37. 개인 사용자로서 실제 사내 연결이 없는 환경에서도 모의 연동으로 성공·실패·재시도 흐름을 검증하고 싶다.
38. 개인 사용자로서 +에서 새 작업·SRD 생성·RP 생성 탭을 열고, 새 작업 탭을 기본으로 보고 싶다.
39. 개인 사용자로서 PRD·제목·상위 페이지 링크를 입력하여 SRD를 생성하고 싶다.
40. 개인 사용자로서 정해진 role을 검색해 여러 개 선택하고 PRD 링크를 입력하여 RP를 생성하고 싶다.
41. 개인 사용자로서 생성 응답을 기다린 뒤 생성된 위키 링크를 확인하고 싶다. 생성한 문서를 작업 목록에서 관리할 필요는 없다.

42. 개인 사용자로서 최초 실행에 Jira·emux PAT를 한 번 설정하고, 이후 앱에서 토큰을 교체하고 싶다.
43. 개인 사용자로서 설정에서 완료 작업을 확인 후 한꺼번에 로컬 삭제하고 싶다.

## Implementation Decisions

### 최초 실행과 설정

- 두 PAT가 키체인에 없으면 최초 설정 화면을 연다. Jira PAT와 emux PAT 모두 입력해야 설정을 완료하며, 이미 저장되어 있으면 다음 실행부터 다시 묻지 않는다.
- 최초 설정 완료 전에는 새 작업 진입과 기존 Jira 요청 재개를 기다린다. 키체인 읽기·쓰기 실패는 오류를 표시하며 설정을 완료한 것으로 처리하지 않는다.
- 최초 설정의 ‘앱 종료’는 토큰을 저장하지 않고 설정 시트를 닫은 뒤 앱을 종료한다. 다음 실행에서는 최초 설정을 다시 요구한다.
- 앱 상단 우측, + 바로 왼쪽에 톱니바퀴 설정 버튼을 둔다. 앱 메뉴의 설정과 메뉴바 팝오버의 기존 설정 진입도 유지한다.
- PAT는 SecureField로 입력하고 macOS 키체인의 기기 전용·동기화하지 않는 항목에 저장한다. 두 값을 한 항목으로 원자 저장하며 일반 DB·UserDefaults·소스·로그에는 기록하지 않는다.
- 설정 화면은 기존 PAT 값을 입력란에 채우지 않는다. 변경할 PAT만 입력하고 업데이트하며 빈 항목은 기존 값을 유지한다. 저장 후 입력값을 비운다. 설정 화면을 닫으면 미저장 입력을 폐기한다.
- 회사 adapter는 TokenVault를 주입받아 요청 시 최신 PAT를 읽는다. 만료·권한 오류는 Jira 실패 흐름에서 표시하고, 사용자 토큰 교체 후 기존 실패 작업을 재시도할 수 있다. 키체인에 값이 있다는 사실은 유효성 검증이 아니다. 현재 mock은 토큰 저장만 제공하며 실제 인증·유효기간 검증은 사내 API 연결 후 수행한다.
- 설정의 “완료 작업 모두 삭제”는 현재 한국 날짜 기준 완료인 작업 전체와 코멘트를 삭제한다. 예정·진행 중 작업과 저장된 PAT는 유지한다. 완료 작업이 없으면 버튼을 비활성화한다.
- 삭제 전에 개수와 기존 로컬 삭제 안내를 담은 확인창을 표시한다. Jira 티켓과 이미 반영된 내용은 남으며 Jira에서는 사용자가 직접 처리한다. 취소하면 삭제하지 않는다. 확인 시 현재 날짜로 삭제 대상을 다시 계산한다.
- 삭제 대상의 미전송 요청은 취소하고 전송 중 요청의 늦은 응답은 기존 정책으로 정리한다. 전체 삭제를 하나의 로컬 DB 저장으로 처리한다.

### 기술과 개발 기본값

- Swift와 SwiftUI로 Mac 네이티브 앱을 만든다. Mac 전용 메뉴바 기능을 제공하면서 별도 웹 런타임과 메인·렌더러 간 통신 구조를 추가하지 않아, 가볍고 구조가 단순한 앱을 우선한다. 플랫폼 기능이 필요한 부분에만 AppKit을 사용한다.
- 저장 방식은 가벼운 로컬 SQLite를 기본값으로 둔다. 외부 DB, 클라우드 동기화, 별도 서버를 설치하지 않는다.
- 첫 버전의 검색은 대소문자 구분 없는 키워드 검색이다. 제목·티켓·코멘트 원문을 대상으로 하며, 비슷한 뜻의 단어까지 추론하는 검색은 제공하지 않는다.
- 사용자에게 표시하는 상태명은 진행 중, 예정, 완료이다. 내부 값은 각각 InProgress, ToDo, Closed를 유지한다. 진행 중을 기본 탭으로 두며 전체 탭은 제공하지 않는다. 각 탭의 작업만 표시하고 기본값은 이름 오름차순이다. 완료 작업은 완료 탭에서만 조회하며 기본 화면에 누적 표시하지 않는다.
- 상태는 텍스트와 작은 색상 점으로 구분한다. InProgress는 파랑(#4F89BC), ToDo는 황토색(#BD913D), Closed는 녹색(#579578) 점을 사용하고 배경과 본문 색은 중성 톤을 유지한다.
- 임의의 운영체제 최소 버전이나 회사 Jira 필드 ID를 추측해서 고정하지 않는다. 구현 환경 확인 후 호환 가능한 최소 버전을 선정하고 Jira 필드·상태 대응은 연결 설정으로 둔다.

### 화면과 입력

- 날짜 선택기 아래 상태 설명 행과 선택 안내·‘기간 다시 선택’ 행은 제거한다. 시작일/종료일 박스를 누르면 다시 선택할 수 있다. 새로 만들기·수정과 캘린더 작업 목록의 스크롤바는 해당 영역만 얇은 네이티브 overlay 스타일과 자동 숨김으로 설정한다. macOS 전체 스크롤바 설정은 바꾸지 않는다.

- 외곽 6px 수정: 캘린더·새 작업/수정·작업 목록은 앱 내부 오버레이로 표시하고 반경을 6/displayScale pt로 직접 그린다. 시스템 sheet/popover 외곽을 사용하지 않는다. 취소·저장·입력창과 앱 창·메뉴바·최초 설정 스타일은 유지한다. 배경은 딤·비활성화하고 hover·클릭은 같은 작업 목록을 연다. 닫기·Esc·상세 이동·생성 중 종료 차단을 유지하며 긴 폼은 스크롤한다.

- 캘린더 작업 목록 팝오버는 날짜 제목 없이, 바깥 여백 8pt·항목 여백 4pt로 표시한다. 작업명 왼쪽의 2pt 세로선을 진행 중 파랑·예정 황토색으로 구분하고 상태 텍스트는 접근성 이름으로 유지한다. 선택적 티켓 ID는 표시하며 스크롤과 상세 이동을 유지한다. 기본 마우스오버 툴팁에서도 날짜 제목을 제거한다.

- 티켓 번호는 비교할 때 대문자로 정규화한다. 동일한 연결 티켓을 가진 기존 작업이 있으면 기존 작업으로 안내하며 조용히 병합하지 않는다.

- 시작일·종료일은 같은 달력의 날짜 범위 선택으로 입력한다. 월·연도 이동과 연도를 넘는 기간 선택을 지원한다.
- 시작일을 선택한 다음 종료일 선택 단계에서는 시작일 이전 날짜를 비활성화한다. 포인터와 키보드 모두 비활성 날짜를 선택할 수 없어야 한다.
- 시작일을 변경해 기존 종료일이 시작일보다 앞서게 되면 종료일을 해제하고 다시 선택하게 한다. 날짜 범위가 완성되기 전에는 저장 버튼을 비활성화한다.
- 화면의 입력 제한과 별개로 저장 경계에서도 날짜 유효성과 제목·티켓 중복을 검증한다.
- 시작일과 종료일이 같은 하루 작업을 허용한다.
- 수정 폼은 현재 값으로 열리고 저장 전까지 실제 기록을 변경하지 않는다. 저장 버튼이 사용자의 최종 확인이다. 유효한 새 작업·수정 폼은 로컬 저장이 확정되면 닫고 선택한 작업 상세에 Jira 처리 중·결과·재시도를 표시한다. 검증 오류가 있으면 폼을 유지한다.
- 수정 폼에서 티켓 추가·변경·제거를 허용하며, 동일 티켓 번호 중복 검증은 유지한다. 티켓을 바꾸면 이후 반영 대상은 새 티켓이며, 이전 티켓에 이미 반영한 변경은 되돌리지 않는다. 이전 티켓에 아직 보내지 않은 요청은 취소하고 전송 중인 요청의 결과는 별도로 관리한다. 과거 코멘트를 새 티켓에 자동으로 재전송하지 않는다.
- 메뉴바 팝오버는 진행 중을 기본 탭으로 두고 예정·완료 탭도 제공한다. 제목 클릭 시 앱을 열어 해당 상태 탭과 작업 상세를 선택하고, 제목 오른쪽 수정 아이콘은 해당 작업의 앱 수정 폼을 연다. 수정 아이콘은 13px로 표시하며 클릭 영역은 24px를 유지한다. 상단 좌측에 아이콘과 Questlet을, 우측에 시안과 동일한 app-window 모양의 앱 열기 아이콘과 + 버튼을 둔다. 앱 열기 버튼은 28px 크기와 1px 테두리·6px 둥근 모서리를 적용한다. +는 앱을 열어 새 작업 폼을 표시한다. 날짜와 하단 푸터는 제공하지 않는다. 빈 상태 탭에는 빈 목록 안내를 표시한다. 목록 영역은 팝오버의 최소 크기 계산에서도 접히지 않도록 높이를 확보하며, 최대 330px 안에서 스크롤한다.

### 데이터와 상태

- 작업은 안정적인 로컬 식별자, 제목, 선택적인 티켓 번호, 시작일, 종료일을 가진다.
- 코멘트는 작업 식별자, 원문, 추출한 링크, 기록 시각을 가진다. 요약을 생성하지 않는다.
- 코멘트를 추가하면 즉시 로컬에 저장하며, 연결 티켓에는 원문을 추가한다. 원문 수정·개별 코멘트 삭제는 첫 버전에서 제외한다.
- 날짜는 한국 시간의 달력 날짜로 처리한다. 기록 시각은 시점을 보존하고 화면에서 한국 시간으로 표시한다.
- 오늘 < 시작일이면 ToDo, 시작일 ≤ 오늘 ≤ 종료일이면 InProgress, 오늘 > 종료일이면 Closed이다.
- 수동 상태 선택은 제공하지 않는다. 종료일을 오늘로 변경하면 다음 날 Closed가 된다. 날짜 선택기 아래에 별도 상태 안내 행은 표시하지 않는다.
- 날짜 수정 직후 상태를 재계산한다. 매일 날짜 변경 시, 앱 시작·잠자기 복귀 시 현재 날짜와 비교하고 필요한 변경만 갱신한다.
- 여러 날 미실행했다면 중간 상태를 순차 반영하지 않고 현재 최종 상태를 반영한다.
- 대화 이력과 별도 변경 이력은 저장하지 않는다. 코멘트와 미처리 Jira 반영 요청은 별개로 보존한다.

### 새 작업·SRD·RP 생성

- 앱의 기존 “+ 새 작업” 버튼을 아이콘만 있는 + 버튼으로 바꾼다. 앱과 팝오버의 +는 동일한 생성 폼을 열며, 매번 기본 탭은 새 작업이다. 접근성 이름과 툴팁은 “새로 만들기”로 한다. 기존 등록 버튼 색은 유지한다.
- 폼 상단에 새 작업·SRD 생성·RP 생성 탭을 둔다. 새 작업은 기존 제목·선택적인 Jira 티켓·기간 폼과 저장 동작을 유지한다. 기존 작업 수정은 별도 수정 폼으로 열며 생성 탭을 제공하지 않는다.
- 생성 탭의 텍스트는 각 탭 영역의 가운데에 정렬한다.
- SRD 생성은 PRD, 제목, 상위 페이지 링크 세 개의 문자열 입력을 받는다. 모두 입력해야 생성할 수 있다. PRD 입력을 링크로 제한하지 않는다.
- RP 생성은 role 다중 선택과 PRD 링크 입력을 받는다. role은 최소 한 개를 선택하며 PRD는 http 또는 https 링크여야 한다. 입력은 문자열 폼으로 제공한다.
- 초기 role 선택지는 cmg_self_service, cmg_reco_valley, cmg_bada, cmg_wing_card이며 이후 추가할 수 있다. 옵션 목록과 검색·선택 UI를 분리하고 네 개라는 개수에 의존하지 않는다. 임의 태그 생성은 허용하지 않는다. 대소문자 구분 없이 부분 일치 검색하며 초기 목록에서 cmg는 네 개, valley는 cmg_reco_valley와 일치한다.
- 후보는 입력 아래에 표시하고 이미 선택한 role은 제외한다. 후보 영역은 최대 3.5행 높이로 제한해 다음 항목 일부가 보이도록 하며, 넘치는 항목은 세로 스크롤과 스크롤바로 조회한다. 후보가 적으면 높이를 줄인다. 위·아래 방향키로 이동한 후보가 화면 밖에 있으면 자동으로 스크롤해 표시한다.
- Enter 또는 마우스로 선택하면 입력 안에 chip으로 추가한다. 동일 role 중복은 허용하지 않으며 등록된 모든 옵션을 선택할 수 있다. 선택 개수를 네 개로 제한하지 않는다.
- 검색 입력이 빈 상태에서 Backspace를 누르면 마지막 chip을 제거한다. 검색어가 있으면 검색어를 지운다. chip마다 제거 버튼도 제공한다. IME 입력 중 Enter는 선택으로 처리하지 않는다.
- 탭 전환 시 각 탭의 미제출 입력을 유지하고 폼을 닫았다 다시 열면 새 작업 기본 탭과 빈 입력으로 시작한다.
- SRD·RP의 CTA는 저장이 아닌 생성이다. 생성 중 폼을 유지하고 처리 중 표시를 제공한다. 중복 제출·입력 변경·탭 전환·폼 닫기를 막으며 UI 자체를 블로킹하지 않는다.
- 생성 완료 후 같은 폼에 API 응답의 위키 링크를 클릭 가능한 링크로 표시한다. 폼을 자동으로 닫지 않고 사용자가 닫도록 한다. 실패 시 입력을 유지하며 같은 화면에서 오류와 재시도를 제공한다.
- 위키 생성 요청의 결과가 불명이면 자동 재생성하지 않는다. 사내 adapter가 중복 방지 또는 기존 생성 결과 확인을 보장하는 경우에만 같은 요청을 안전하게 재시도한다. 지원하지 않으면 사내 위키에서 생성 여부를 확인하도록 안내한다.
- 현재 SRD·RP 실제 API는 연동하지 않는다. 각각의 생성 요청과 결과 링크를 받는 교체 가능한 연결 지점을 두고, 모의 API는 약 10초 대기 후 예시 위키 링크를 반환한다. 결과는 모의 링크라고 표시하며 실제 문서가 생성됐다고 표현하지 않는다. 사내 URL과 API 계약은 추측하지 않는다.
- SRD·RP 결과는 작업 목록·팝오버·로컬 DB에 등록하지 않는다. 생성 내역·검색·동기화·재실행 후 생성 요청 복구는 첫 버전에서 제공하지 않는다. 새 작업의 SQLite 저장과 Jira 요청 정책은 기존대로 유지한다.

### Jira 연결과 결과 확인

- JiraTicketModule, SRDGenerationModule, RPGenerationModule의 입력·출력·오류 계약은 INTEGRATION-INTERFACES.md를 따른다. mock/사내 adapter 교체 위치와 호출 시점은 INTEGRATION-GUIDE.md에 정리한다. 실제 Sources 경로와 adapter 교체 순서는 INTEGRATION-GUIDE.md에 기록한다.
- 사용자는 사내에서 Jira 직접 호출과 토큰 사용을 확인했다. 첫 버전은 emux를 호출하지 않는다.
- 실제 인증 방식·호스트·날짜 필드·상태 전환 대응은 사내 호출 계약에 맞춰 주입한다. 이번 구현에서 실제 토큰을 요구하거나 운영 Jira를 변경하지 않는다.
- 모의 연결과 실제 연결을 교체하는 하나의 Jira 연결 경계를 둔다. 앱에서 직접 호출하거나 사내 스크립트를 통해 호출할 수 있게 계약을 분리한다.
- 작업과 해당 Jira 반영 요청을 로컬에 함께 확정한다. 사용자 입력에 따른 등록·수정·코멘트 추가는 Jira 응답까지 기다린 뒤 작업 상세에 완료 결과를 표시한다. 폼 닫힘은 로컬 저장의 확정이며 Jira 반영 완료를 뜻하지 않는다. 실패해도 로컬 변경은 유지하며, 같은 화면에서 로컬에는 저장됐지만 Jira 반영은 실패했다고 알린다.
- 요청은 비동기로 실행해 화면 응답을 막지 않는다. 처리 중 표시를 제공하고 같은 작업의 중복 제출을 막는다. 제한 시간 내 응답이 없으면 실패 또는 결과 불명을 같은 화면에 표시한다.
- 사용자 입력으로 발생한 실패에 대해 별도 시스템 알림이나 추후 알림 기능은 구현하지 않는다. 같은 화면에 재시도를 제공한다.
- 티켓이 없는 작업에는 Jira 반영 요청을 만들지 않는다.
- 연결 티켓의 날짜·상태·원문 코멘트만 반영하며, Jira 제목 변경과 티켓 생성·삭제는 제공하지 않는다.
- 일정 변경은 폼 저장으로 확정된 값을 반영한다. 매일 자동 상태 변경은 사용자가 폼을 제출하지 않으므로 백그라운드에서 반영하며, 실패는 앱 상세에서 확인·재시도할 수 있게 한다. 자동 변경에도 시스템 알림은 보내지 않는다.
- 결과 불명 요청은 자동 재전송하지 않는다. Jira를 직접 확인한 사용자는 “이미 반영됨”으로 요청을 정리하거나 “미반영 확인”으로 재전송을 선택할 수 있다.
- 요청은 재실행 후 복구 가능한 형태로 저장한다. 같은 티켓의 변경은 순서를 지키고 아직 전송하지 않은 일정·상태 변경은 최신 값으로 합친다. 코멘트 요청은 각각 유지한다.
- 날짜·상태·코멘트 중 일부만 성공하면 성공한 부분을 다시 실행하지 않고 실패한 부분만 재처리한다.
- 사용자 입력 요청이 실패하면 같은 화면에서 사용자 재시도를 기다린다. 자동 상태 갱신의 일시적 연결 실패와 중단된 요청은 재실행·복귀 시 재개하며, 인증·권한·설정 오류는 실패로 표시하고 설정 수정이나 사용자 재시도를 기다린다.
- 코멘트 전송 후 응답이 유실되면 성공 여부를 먼저 확인한다. 확인할 수 없다면 결과 불명으로 표시하고 자동 재전송을 멈춰 중복을 막는다.
- 미연동 모드는 실제 반영 대기 또는 미연동이라고 표시한다. 모의 실행 결과는 모의 결과임을 명시한다.
- 운영 연결에 토큰이 필요하면 소스·일반 DB·로그에 기록하지 않는다. Mac Keychain 저장을 기본값으로 제안한다.

### 삭제

- 확인 후 작업과 소속 코멘트를 로컬에서 삭제한다. 보관·복원 기능은 첫 버전에서 제공하지 않는다.
- 아직 전송하지 않은 Jira 반영 요청은 취소한다.
- 이미 전송 중인 요청은 취소됐다고 보장하지 않는다. 삭제 확인에 이를 표시하고, 늦은 응답으로 삭제한 작업을 다시 생성하지 않는다.
- Jira 티켓과 이미 올라간 코멘트·변경은 삭제하거나 되돌리지 않는다. 사용자에게 Jira에서 직접 처리하도록 안내한다.

## Testing Decisions

핵심 저장·연동 흐름의 자동 검증을 구현하고 실행했다. 아래 목록은 전체 검증 목표이며 실행한 범위와 UI 검증의 제한은 IMPLEMENTATION.md에 기록한다.

- 핵심 검증은 사용자 행동부터 영속 저장과 Jira 모의 요청까지 이어지는 흐름을 대상으로 한다. 사내 연동 seam은 Jira 변경·SRD 생성·RP 생성의 세 interface로 제한하고 각 mock adapter를 통해 검증한다.
- 날짜 경계는 실제 시각을 기다리지 않고 제어한 날짜로 검증한다. 시작일 전날·당일, 종료일 당일·다음 날, 하루 작업, 한국 자정, 연장 후 재계산을 포함한다.
- 폼 등록 후 재실행해 기록이 남는지, 티켓·제목 중복 차단, 티켓 없는 작업의 동일 제목 차단, 수정 중 자신의 제목 유지, 수정 취소와 저장을 검증한다.
- 시작일 이전 종료일이 키보드와 포인터로 모두 선택 불가인지, 시작일 변경 시 잘못된 종료일이 해제되는지, 기간 미완성 시 저장 불가인지 검증한다.
- 팝오버 기본 진행 중 탭과 예정·완료 전환, 창 아이콘으로 앱 열기, +로 앱의 새 작업 폼 열기, 제목으로 해당 작업 상세 열기, 연필로 수정 폼 열기를 확인한다.
- 코멘트 원문·링크·기록 시각 보존과 yyyy/MM/dd HH:mm 표시, 제목·티켓·코멘트 키워드 검색을 검증한다. 검색은 현재 탭에 한정되고 완료 탭에서도 동작해야 한다.
- 유효한 새 작업·수정 저장 후 폼이 닫히고 해당 작업 상세가 선택되는지, 검증 오류 시 폼이 유지되는지 확인한다. 폼이 닫힌 뒤 Jira 처리 중·성공·실패·재시도를 상세에서 확인할 수 있어야 한다.
- 지연된 모의 Jira 응답에서도 로컬 저장은 유지되고 화면은 응답하며, 처리 중 표시와 중복 제출 방지를 제공하고 Jira 응답 전에는 반영 완료로 표시하지 않는지 확인한다.
- 성공·실패·제한 시간 초과를 같은 화면에 표시하고 실패한 경우 재시도할 수 있는지 검증한다. 티켓 없는 작업은 Jira 대기 없이 완료해야 한다.
- 실패 후 로컬 데이터 유지, 재실행 후 요청 재개, 연속 일정 수정의 최종 값, 여러 코멘트 보존, 부분 성공과 결과 불명 코멘트 처리를 검증한다.
- 로컬 삭제 후 미전송 요청 취소, 늦은 응답에 의한 작업 재생성 방지, Jira 삭제를 실행하지 않는 것을 검증한다.
- PAT 최초 설정·재실행·개별 교체·빈 값 유지·키체인 오류를 확인하며, 실제 PAT를 테스트 소스에 기록하지 않는다. 완료 일괄 삭제의 날짜 경계·코멘트 제거·요청 취소·취소 버튼과 Jira 안내를 확인한다.
- 실제 사내 Jira 검증은 연결 계약이 확보된 뒤 테스트 티켓으로 수행한다. 모의 성공만으로 실제 반영 검증을 완료했다고 보고하지 않는다.
- 앱·팝오버 + 진입 시 새 작업 기본 탭과 SRD·RP 전환, 탭별 입력 유지, 작업 수정에서 생성 탭 미표시를 확인한다.
- SRD 세 문자열과 RP role·PRD 링크 검증, cmg·valley 부분 검색, 선택된 role 제외, Enter·마우스 선택, 중복 방지, 전체 옵션 선택, 빈 입력 Backspace 제거를 확인한다. role 옵션을 추가해도 동작하고 후보 최대 3.5행·스크롤바·키보드 이동에 따른 자동 스크롤이 유지되는지 확인한다.
- SRD·RP 생성 중 약 10초 대기와 중복 제출 방지, 응답 링크 표시, 모의 결과 표시, 실패 시 입력 유지·재시도를 확인한다. 생성으로 작업 목록이나 로컬 DB에 문서 기록이 추가되지 않아야 한다.
- 위키 생성 응답 유실이나 잘못된 응답 URL은 결과 불명으로 구분하고 자동 재생성하지 않는다. 안전한 중복 방지 또는 원격 결과 확인이 가능한 경우에만 같은 요청을 재시도한다.
- UI는 날짜 범위 선택, 키보드 입력, 팝오버와 창 이동, 실패 표시를 실행 화면에서 확인한다. 기본 진행 중 탭, 완료 분리, 코멘트 개수, 연도 표시, 상태 점, 링크 클릭, 편집 아이콘과 티켓 수정도 확인한다.

## Out of Scope

- SRD·RP 실제 API 연동과 생성 내역 관리. 첫 버전에는 생성 폼과 모의 API만 포함한다.
- emux·AI·에이전트 프롬프트·스킬과 채팅 UX.
- 자연어 등록·수정·검색과 자동 제목·코멘트 요약.
- 캘린더에서 드래그로 일정을 변경하거나 주간 시간표를 편집하는 기능. 날짜별 조회 캘린더와 폼 날짜 선택기는 포함한다.
- Jira에서 로컬로 가져오는 양방향 동기화.
- Jira 티켓 생성·삭제·제목 수정과 이미 반영한 변경 되돌리기.
- 기기 간 공유·클라우드 DB 동기화·팀 협업.
- 별도의 실제 완료 상태와 수동 상태 변경.
- 대화 이력·독립적인 변경 이력·작업 복원.
- 코멘트 수정·개별 삭제. 기존 작업의 티켓 연결 변경은 포함한다.

## Further Notes

- 이 앱의 Closed는 실제 완료 검증이 아니라 예정 종료일이 지났다는 의미다. UI에 자동 상태 규칙을 명시한다.
