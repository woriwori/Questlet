# Questlet 구현 기록

2026-10-03. macOS SwiftUI + AppKit 메뉴바 + 시스템 SQLite. 외부 패키지를 추가하지 않았다.

## 구현 범위

- 로컬 작업 등록·수정·삭제, 제목/티켓 중복 방지, 날짜 범위 선택, 한국 날짜 기반 예정·진행 중·완료 상태.
- 전체 행 클릭, 티켓 링크, 코멘트 개수, 원문 메모·링크·연도 포함 기록 시각, 현재 탭 키워드 검색.
- 창과 메뉴바 팝오버, 앱 열기·+·수정, 창 종료 후 메뉴바 유지, 시작·날짜 변경·잠자기 복귀 상태 갱신.
- 로컬 저장과 Jira 요청의 원자적 기록, 티켓별 실행 순서, 성공한 요청 제거, 실패 재시도, 일정/상태 병합, 삭제 후 늦은 응답 처리.
- 결과 불명 요청 자동 중단과 사용자 직접 확인 후 정리/재전송. 앱 종료 중 결과가 유실된 코멘트도 재전송을 멈춘다.
- 새 작업/SRD/RP 탭, 탭별 초안 유지, SRD 문자열 입력, RP role chip·부분 검색·Enter·방향키·빈 입력 Backspace, 최대 3.5행 후보 스크롤.
- SRD/RP 10초 mock 대기, 입력 잠금, 링크 표시·복사, 실패 입력 유지, 결과 불명 자동 재생성 방지. 생성 내역은 DB에 남기지 않는다.
- 세 사내 adapter 골격과 주입 지점, 입력·출력 문서, 역할 목록 JSON 설정, 실행·검증 스크립트.

## 적용한 스킬

vercel-react-best-practices와 vercel-composition-patterns를 읽고 상태 소유·재사용 컴포넌트·주입 원칙을 적용했다. 앱은 합의한 SwiftUI이며 React/Next 전용 최적화를 적용했다고 주장하지 않는다. Ponytail lite는 시스템 API 우선, 추가 의존성 없음, 단순한 세 연동 경계와 SQLite snapshot 저장으로 적용했다. 선행 codebase-design 계약을 실제 소스 경계로 구현했다.

## 확인한 범위

`./scripts/check.sh`가 전체 앱과 핵심 모듈을 컴파일하고 흐름 검증을 통과했다. 날짜 시작/종료 경계와 한국 자정, 잘못된 날짜·기간, 중복 제목, SQLite 재읽기, 원문 코멘트·링크·시각, 검색, Jira 날짜 성공 후 상태 실패·재시도·동일 요청 ID 유지, 코멘트 전송, 종료 후 연장 상태, 결과 불명 코멘트 재시작 시 중복 방지, 삭제, SRD/RP mock 계약과 5개 role 허용을 확인했다.

macOS 26.6.2 Apple Silicon에서 앱 실행과 실제 창의 작업 목록·상세·메모 표시를 확인했다. UI 자동 조작 중 사용자의 앱 조작이 감지돼 경쟁하는 입력을 중단했다. 따라서 모든 폼·키보드·메뉴바 행동의 자동 UI 검증을 완료한 것은 아니다. 코드 빌드와 핵심 흐름 검증은 통과했다.

실제 사내 Jira/SRD/RP 호출과 Intel Mac 실행은 검증하지 않았다. 현재 모두 mock이고 example.com 위키 링크는 모의 결과다. 사내 연결 체크는 INTEGRATION-GUIDE.md를 따른다.

## 빌드와 데이터

현재 설치된 SwiftPM 실행 파일의 프레임워크 심볼 오류와 기본 SDK 불일치를 피하기 위해 swiftc와 명시적 MacOSX26.5 SDK로 빌드했다. scripts/build.sh가 dylib·리소스를 포함한 앱을 만들고 로컬 ad-hoc 서명한다. Apple 배포용 공증은 하지 않았다. Package.swift도 포함했다.

작업·코멘트·미처리 요청을 SQLite 한 행의 JSON snapshot으로 저장한다. 개인 업무 규모에 맞춘 선택이다. 큰 규모에서 읽기/저장 비용이 문제가 되면 Database 내부를 행 단위로 바꾸고 AppModel과 연동 계약은 유지한다. DB가 손상되거나 버전이 다르면 시작 오류를 표시하고 기존 데이터를 덮어쓰지 않는다.

## 팝오버 수정과 오늘 시작일 기본값

2026-10-03 추가 요청 반영. ScrollView의 maxHeight만 지정하면 팝오버의 압축 높이 측정에서 목록이 0으로 줄었다. 실제 MenuPopover를 NSHostingController로 측정하는 scripts/check-ui.sh에서 수정 전 93pt(헤더+탭만), 수정 후 작업 한 개 기준 177pt를 확인했다. 목록 높이를 작업 수에 따라 확보하고 최대 330pt로 제한했다. 동일 뷰를 띄운 검증 창에서 진행 중·예정·완료 각 작업 표시를 확인했다.

앱 열기는 승인 시안의 app-window 도형을 직접 그리며 28pt 버튼에 1pt 테두리와 6pt 둥근 모서리를 적용했다. 새 작업 TaskDraft는 한국 날짜 기준 오늘을 시작일로 초기화하며 종료일은 비운다. 수정 Draft는 기존 기간을 유지한다. 이 기본값도 UI 회귀 검사에서 검증한다.

검증: ./scripts/check.sh, ./scripts/check-ui.sh. 압축 레이아웃 검사와 각 탭의 동일 팝오버 뷰 검증을 수행했으며, macOS 메뉴바 클릭 자체의 자동 입력은 도구로 접근할 수 없어 대체 창에서 확인했다. 검증용 창은 --show 옵션으로만 표시한다.

## 메뉴바 로고와 팝오버 수정 아이콘 크기

팝오버 연필 glyph를 18pt에서 13pt로 약 28% 축소하고 24pt 클릭 영역은 유지했다. 메뉴바의 note.text 심볼은 앱 헤더와 동일한 questlet-header.png로 교체했다. NSImage 자체 크기를 18pt로 지정하며 원본 색상을 유지한다. 단색 template로 렌더링하면 종이 면까지 채워져 형태가 달라지므로 original 렌더링을 사용한다.

메뉴바 로고 크기는 후속 요청에 따라 18pt에서 22pt로 확대했다. 원본 비율과 색상은 유지한다.

앱 패키지 아이콘은 scripts/render-app-icon.swift에서 기존 로고의 투명 여백을 각 변 8px씩 줄인 영역(128 → 112px)을 렌더링해 약 14% 확대했다. 원본 로고와 앱 헤더·메뉴바 리소스는 유지하며 build.sh가 확대된 앱 아이콘으로 icns를 만든다.

## 최초 PAT 설정과 완료 작업 정리

Jira·emux PAT를 최초 실행에서 한 번 입력하고, 앱 상단 + 왼쪽 톱니바퀴에서 교체한다. Sources/QuestletCore/TokenVault.swift의 KeychainTokenVault가 두 PAT를 하나의 기기 전용·비동기화 generic-password 항목에 저장한다. 기본 service는 local.questlet.api-tokens다. TokenVault는 IntegrationAssembly에 주입되어 회사 adapter가 요청마다 최신 값을 읽을 수 있다. SecureField는 기존 값으로 채우지 않으며, 한 PAT만 교체할 때 빈 다른 필드는 기존 값을 유지한다. mock은 유효기간·실제 인증을 검사하지 않는다.

설정의 완료 일괄 삭제는 현재 한국 날짜 기준 완료 작업과 코멘트를 하나의 SQLite 저장으로 삭제한다. 미전송 요청은 취소하고, 진행 중 요청은 늦은 응답 정리까지 유지한다. Jira 삭제 호출은 없다. 확인창은 Jira와 이미 반영된 내용이 남는다는 기존 안내를 사용한다.

검증: 실제 키체인의 임시 테스트 항목으로 최초 저장·새 provider에서 재읽기·각 PAT 교체·빈 값 유지·누락 입력 차단을 검증하고 테스트 항목을 삭제했다. 실제 사용자 PAT는 사용하지 않았다. 완료만 일괄 삭제·종료일 당일 보존·오래된 상태 재계산·코멘트와 미전송 요청 제거·실행 중 요청 보존·SQLite 재읽기를 검증했다. 테스트 TokenVault로 최초 실행과 재실행 분기를 확인했다. 동일 뷰의 검증 창에서 최초 설정·설정 화면·로컬 삭제 안내·취소 후 개수 유지를 확인했다. 실제 사내 API 인증과 PAT 만료 응답 검증은 사내 연동 이후 수행해야 한다.
