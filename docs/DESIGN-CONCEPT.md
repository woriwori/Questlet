# Questlet 디자인 컨셉 — 확정

작성일: 2026-10-03. frontend-design 지침과 프로젝트 명세를 바탕으로 만든 디자인이며 2026-10-03 사용자가 승인했다. 목록 + 상세와 메뉴바 팝오버를 구현 기준으로 확정했다. 실제 SwiftUI 구현은 아직 시작하지 않았다.

## 방향

연한 중성 회색, 읽기 편한 검정, 충분한 여백으로 조용한 업무 도구를 만든다. 사용자가 말한 Codex의 연한 톤을 참고하되 현재 앱 화면을 직접 관찰한 것은 아니다. 장식보다 작업 제목과 기간을 빠르게 읽고 수정하는 흐름을 우선한다.

선택한 작업과 작업 제목을 강조한다. 큰 상태별 카드, 통계 대시보드, 고정 사이드바, 그라데이션, 반복되는 그림자는 사용하지 않는다. 주요 행동은 등록, 작업 정보 수정, 코멘트 추가다.

## 색

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| Surface | #FCFCFC | 창 본문, 폼, 팝오버 |
| Quiet | #F4F5F6 | 타이틀바, 목록, 입력 영역 |
| Line | #E5E7E9 | 영역 분리선 |
| Ink | #282D33 | 제목, 본문, 주요 버튼 |
| Secondary | #6E747C | 티켓, 기록 시각, 보조 설명 |
| Focus | #577188 | 선택 표시, 기간 시작·종료일 |

포커스 색의 연한 배경은 Focus를 낮은 비율로 섞어 만든다. 상태 점은 진행 중 #4F89BC, 예정 #BD913D, 완료 #579578로 구분하고 텍스트 라벨을 함께 사용한다. 색상은 작은 점에만 적용하고 배경과 제목은 중성 색을 유지한다. 오류는 작은 붉은 문장과 재시도 버튼으로 표시하고, 전체 화면을 붉게 만들지 않는다.

## 글자와 간격

- Mac 시스템 글꼴을 사용한다. SwiftUI에서는 시스템 서체로 구현하고, 한국어는 운영체제의 기본 한국어 폴백을 따른다.
- 창 제목 15pt, 작업 상세 제목 22pt semibold, 목록 작업명 14pt semibold, 본문 13pt, 보조 정보 12pt를 기준으로 제안한다. 목록은 제목, 티켓·코멘트 개수, 기간의 세 줄이다. 목록의 말풍선은 10px로 작게 표시하고 상세의 개수는 제목 옆에 둔다.
- 본문은 regular, 제목과 주요 행동만 medium/semibold. 티켓 번호에 별도 장식용 고정폭 서체를 쓰지 않는다.
- 본문은 왼쪽 정렬한다. 날짜와 티켓은 숫자 정렬이 필요한 위치에서만 고정폭 숫자를 사용한다.
- 8pt 간격 단위, 본문 바깥 여백 24pt, 작업 행 높이 약 68pt. 폼·입력의 모서리는 6~8pt로 작게 둔다.

## 확정안: 목록 + 상세

```text
┌ 창 제어 ───────────── Questlet ───────────────┐
│ Questlet                     [새 작업]     │
│ [제목, 티켓, 코멘트 검색]                  │
├──────────────────┬────────────────────────┤
│ [● 진행 중] [● 예정] [● 완료]         │
│ ▸ 캠페인 수정    │ 캠페인 수정 💬2  [편집]│
│   CMGSL-13332 💬2│ CMGSL-13332 ↗           │
│   2026/10/01—05  │ ● 진행 중            │
│   로그인 오류    │ 2026/10/01—2026/10/05   │
│                  │                        │
│                  │ 날짜가 붙은 메모들       │
│                  │ 기록 시각 / 원문 / 링크 │
│                  │ [코멘트 입력] [추가]    │
└──────────────────┴────────────────────────┘
```

목록을 유지한 채 상세를 바꿔 여러 작업을 빠르게 오갈 수 있다. 기본 탭은 진행 중이고 전체 탭은 제거한다. 완료는 해당 탭에서만 표시한다. 검색은 현재 상태 탭을 대상으로 한다. 추가적인 메뉴나 사이드바 없이 한 창에서 조회와 수정 진입을 제공한다.

## 비교 기록: 단일 목록 (구현 대상 제외)

전체 폭에 동일한 세 줄 작업 목록을 제공한다. 작업을 선택하면 상세 시트를 연다. 창은 더 단순하지만 여러 작업의 코멘트를 비교할 때 열고 닫는 동작이 늘어난다. 개인 작업을 조금씩 자주 수정하는 현재 목적에는 목록 + 상세를 우선 추천한다.

## 등록·수정 폼

```text
┌ 새 작업 ─────────────────────────┐
│ 제목 [캠페인 수정 버그픽스      ] │
│ 티켓 [CMGSL-13332              ] │
│                                  │
│ 시작일        종료일              │
│ 2026/10/03    2026/10/07          │
│        ‹ 2026년 10월 ›            │
│       일 월 화 수 목 금 토        │
│        하나의 날짜 범위 달력      │
│                                  │
│ 종료일 당일까지 진행 중       │
│                    [취소] [저장] │
└──────────────────────────────────┘
```

- 시작일을 선택한 뒤 그 이전 날짜는 종료일로 선택할 수 없도록 비활성화한다. 같은 날 시작·종료는 허용한다.
- 시작·종료를 모두 선택하기 전 저장 버튼은 비활성화한다. 종료일까지 범위를 연하게 연결하고 양 끝만 짙게 표시한다.
- 제목·티켓 중복 오류는 해당 필드 가까이에 표시한다. 제목이나 기간이 잘못된 상태에서 Jira 요청을 시작하지 않는다.
- 유효한 저장은 로컬 확정 후 폼을 닫는다. Jira 처리 중·성공·실패와 재시도는 상세에 표시한다. 단일 목록 구성에서는 목록 위에 표시한다. 검증 오류가 있으면 폼을 유지한다.
- 실패 문구는 “로컬에 저장했습니다. Jira 반영에 실패했습니다.”와 재시도다. 모의 연동에서는 모의 응답임을 표시한다.

## 작업 상세와 코멘트

강조한 제목과 코멘트 개수를 위에 두고, 그 아래 티켓 링크·상태 점과 라벨·연도 포함 기간을 같은 수준의 메타데이터로 묶는다. 제목 옆 연필 아이콘으로 제목·티켓·기간 수정 폼을 연다. 기간만을 위한 별도 버튼이나 큰 영역은 제거한다. 날짜 자동 상태를 선택 가능한 메뉴처럼 표현하지 않는다. 별도 게시글 본문은 두지 않는다. 메타데이터 다음에 연한 배경의 메모들을 바로 나열한다. 원문은 14pt로 읽기 쉽게 표시하고 시각은 `2026/10/02 16:20` 형식이다. 입력은 메모 목록 바로 아래에 두며 “코멘트 N”, “코멘트 추가” 라벨은 생략한다.

티켓 링크는 목록·상세·팝오버에 독립적인 클릭 대상으로 제공한다. 링크를 작업 선택 버튼 안에 중첩하지 않는다. 시안에서는 실제 Jira 주소 연결 전 안내를 표시하며 회사 URL을 임의로 넣지 않는다.

삭제는 상세 제목 옆 휴지통 아이콘에서 진입하고 확인을 거친다. 기본 화면에서 삭제를 주요 행동처럼 강조하지 않는다. 삭제 안내에 Jira 티켓은 남는다고 명시한다.

## 메뉴바 팝오버

```text
┌ [아이콘] Questlet ── [창] [+] ┐
│ [● 진행 중] [● 예정] [● 완료] │
│ 캠페인 수정 버그픽스   [편집] │
│ CMGSL-13332 ↗  💬2            │
│ 2026/10/01 — 2026/10/05       │
└──────────────────────────────┘
```

폭 약 340pt로 앱과 같은 상태 탭을 제공하며 기본값은 진행 중다. 상단 우측에는 앱 열기 창 아이콘과 새 작업 + 버튼을 배치하고 날짜와 푸터는 제거한다. 제목 오른쪽의 작은 연필 아이콘은 제목·티켓·기간을 함께 수정하는 앱 폼으로 연결한다. 제목 클릭은 앱 상세를 연다. 빈 탭은 “이 상태에 해당하는 작업이 없습니다.”를 표시한다.

## 검토와 한계

처음 생각한 고정 상태 사이드바는 상태 필터와 역할이 중복돼 제외했다. 카드 형태의 작업 목록도 기간을 빠르게 훑는 목적에 비해 장식이 많아 행 목록으로 바꿨다. 등록 폼에는 통계나 AI 설명을 넣지 않았다.

검토용 화면은 브라우저로 구성한 와이어프레임이다. 실제 macOS 창·팝오버·키보드 접근성 구현과 SQLite/Jira 연결은 포함하지 않는다. 화면의 샘플 작업·링크·모의 응답은 디자인 검토용이다.

클릭 가능한 버튼·링크는 포인터 커서를 사용하며, 입력·비활성 컨트롤의 커서는 구분한다. 목록과 메뉴바 팝오버는 제목 → 티켓·작은 코멘트 말풍선 → 기간 순서를 공유한다.

### 화면 표기 변경 — 2026-10-03

- 앱 콘텐츠 상단 좌측 제목은 아이콘과 함께 `Questlet`으로 표시한다.
- 앱·팝오버 탭, 상세 상태, 폼 안내의 사용자 표기는 `진행 중`, `예정`, `완료`로 통일한다. 기존 영문 화면 표기 결정을 대체한다.
- 내부 상태 값은 `InProgress`, `ToDo`, `Closed`를 유지하며 각각 `진행 중`, `예정`, `완료`로 표시한다. 날짜에 따른 상태 계산은 동일하다.

### 브랜드와 등록 버튼 — 2026-10-03

- 새 작업 버튼과 팝오버 + 버튼은 연필의 파란 계열을 유지하되 밝기·채도를 낮춘 `#56729A`를 공통 사용한다. 글자와 +는 흰색, hover는 `#486386`이다.
- 팝오버 앱 이름 왼쪽에 동일한 노트 + 연필 아이콘을 표시한다. 앱 열기 우측에는 + 버튼을 배치하고, 클릭 시 앱을 열어 새 작업 폼을 표시한다.
- 아이콘과 이름 간격은 앱 4px, 팝오버 3px로 줄인다.

### 팝오버 크기 균형 — 2026-10-03

- 상태 탭 12px를 유지하고 작업 제목 12px, 티켓·개수·기간 11px, 행 여백 8px로 줄인다. 제목은 굵기로 구분한다.
- 브랜드 아이콘 영역은 32px, 앱 이름은 15px로 조금 키운다.
- 상단 앱 열기와 +는 28px 정사각 버튼, 내부 아이콘은 14px로 줄인다. 앱 열기는 텍스트와 화살표 대신 `app-window` 창 아이콘을 사용한다. 접근성 이름과 툴팁은 앱 열기로 유지한다. 링크용 화살표와 의미를 구분한다.

- 티켓번호와 링크 아이콘 간격은 2pt, 팝오버 수정 연필은 18pt, 버튼 영역은 24pt로 확정했다. 웹 시안의 px 수치는 네이티브 구현에서 pt를 기준으로 옮긴다.

## 생성 화면 추가 — 2026-10-03

기존 + 새 작업 버튼은 +만 표시한다. 앱·팝오버의 +는 새로 만들기 폼을 연다. 기존 연한 톤과 작은 상태 탭 스타일을 그대로 사용해 새 작업·SRD 생성·RP 생성 탭을 배치하며 새 작업이 기본이다. 작업 수정 폼에는 이 탭을 넣지 않는다.

SRD는 PRD·제목·상위 페이지 링크 입력, RP는 role chip 입력과 PRD 링크 입력을 제공한다. role 후보는 입력 바로 아래에 놓고 이미 선택한 항목은 제외한다. SRD·RP CTA는 생성이다. 생성 중 폼을 유지하고 응답 후 위키 링크와 닫기를 표시한다. 문서 목록이나 내역 화면은 만들지 않는다. 현재 시안은 10초 대기 후 모의 링크를 반환한다.

role 후보 영역은 최대 3.5행 높이로 제한하고 세로 스크롤바를 제공한다. 초기 네 role 외에 옵션이 늘어나도 같은 검색·chip 선택 UI를 사용한다.

### 클릭 영역과 생성 탭 정렬 — 2026-10-03

- 생성 탭 텍스트는 가운데 정렬한다. 앱·팝오버 목록의 작업 선택 영역은 행 전체다. 티켓번호와 링크 아이콘은 하나의 독립 링크 영역이며 수정 아이콘도 행 선택과 분리한다.
