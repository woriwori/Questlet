# Questlet 캘린더 · 확정 디자인 반영 (2026-10-19)

## 화면

외곽 모서리를 약 절반으로 줄이는 후속 요청에 따라 캘린더·새 작업 시트와 메뉴바 팝오버에 6pt, 캘린더 작업 목록 팝오버에 4pt를 지정한다. macOS 기본값에 맡기지 않고 presentationCornerRadius로 지정하며 Palette에 값을 모은다. 내부 입력창·버튼의 모서리는 유지한다.

작업 중 잠깐 확인하고 닫는 월간 시트로 표시한다. 닫으면 목록·선택·검색·정렬을 유지한다. 날짜 오른쪽에는 SF Symbol calendar를 둔다.

- 너비 600pt, 5주인 달의 높이 422pt. 실제 월의 주 수에 따라 4주는 364pt, 6주는 480pt다. 빈 마지막 주를 추가하지 않는다.
- 좌우·상단 여백 24pt, 하단 padding 36pt. 날짜 칸은 58pt 높이다.
- 날짜는 좌측 상단에 두며 오늘만 작은 둥근 사각형으로 강조한다. 칸 배경을 채우지 않고 위쪽에 얇은 구분선을 둔다.
- 날짜 칸에 점·작업 개수·텍스트 라벨을 표시하지 않는다. 하단 안내 문구도 없다.
- 진행 중 작업이 있으면 위에 연한 파랑 막대, 예정 작업이 있으면 아래에 연한 황토색 막대를 표시한다. 둘 다 있으면 두 줄이며 한 상태의 작업이 여러 개여도 막대는 하나다. 예정만 있는 날에도 아래 줄을 사용한다.
- 파랑은 #4F89BC의 14% opacity, 황토색은 #BD913D의 17% opacity다. 기본 배경 #FCFCFC, 본문 #282D33, 보조 텍스트 #6E747C, 오늘 강조 #56729A를 유지한다.
- 월 제목 18pt semibold, 날짜 12pt, 요일·오늘 버튼 11pt다.
- ‘오늘’, 이전 달, 다음 달, 닫기의 보이는 간격은 14pt 기준이다. 13pt 아이콘과 27pt 버튼, 간격 0으로 구성하고 오늘 버튼과 아이콘 그룹 사이에 7pt를 둔다.
- 앱 상단 날짜·달력·설정·+도 보이는 간격을 같은 14pt 기준으로 맞춘다. 달력·설정은 16pt glyph와 30pt 버튼이며 두 버튼 사이 간격은 0이다. 날짜와 이 그룹, 그룹과 + 사이에는 각각 7pt를 둔다. +는 기존 32pt를 유지한다.

## 작업과 조작

오늘의 한국 날짜로 상태를 다시 계산해 진행 중·예정 작업만 사용하며 완료 작업은 제외한다. 저장된 상태가 오래되어도 날짜 기준을 우선한다. 해당 작업의 시작일~종료일(양끝 포함)에만 막대를 표시한다. 따라서 현재 진행 중인 작업과 미래 예정 작업의 기간이 겹치면 파랑·황토색이 함께 표시된다. 티켓 없는 로컬 작업도 포함하고 검색·사이드바 상태와는 독립적이다.

마우스오버 기본 툴팁에는 각 작업의 상태와 이름을 표시하고 날짜 제목은 넣지 않는다. 날짜 클릭 시 스크롤 가능한 목록을 열고 항목을 선택하면 달력을 닫아 상세로 이동한다. 클릭 목록도 날짜 제목을 제거하고 바깥 여백은 16→8pt, 항목 여백은 8→4pt로 줄인다. 작업명 왼쪽에 2pt 세로선으로 상태를 표시한다. 진행 중은 파랑, 예정은 황토색이며 70% opacity다. 상태 텍스트 대신 세로선을 쓰고 선택적인 티켓 ID는 유지한다. 접근성 이름에는 상태를 포함한다. 이전·다음 달, 오늘, 닫기, Esc 동작을 유지한다. API 호출이나 DB 변경은 없다.

## 구현과 검증

- TaskViews.swift: 상단 아이콘 그룹과 간격, 시트 표시.
- WorkCalendarView.swift: 월간 화면·두 색상 막대·툴팁·날짜 클릭 목록.
- QuestletCore/WorkCalendar.swift: 4/5/6주 구성, 월 이동, 현재 진행·예정 작업 기간 검색.
- scripts/check.sh: 윤년, 일요일 시작, 주 수, 연도·월 경계, 기간 양끝, 상태 캐시 무시, 진행·예정 기간 겹침, 완료 제외와 기존 흐름.
- scripts/check-ui.sh: 실제 컴포넌트의 600pt 너비와 4/5/6주 높이 및 기존 팝오버 회귀 검사.
- --render-calendar <PNG 경로>: 임시 DB 샘플로 실제 컴포넌트를 렌더링한다. 사용자 작업·PAT는 사용하지 않는다.

렌더링 결과를 최종 시안과 비교했다. 실제 마우스 hover, 네이티브 시트·Esc·중첩 팝오버 선택의 자동 UI 조작은 수행하지 않았다.
