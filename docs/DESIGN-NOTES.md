# Mac 개인 업무 지원 앱 — 인터뷰 기록

기록일: 2026-10-01. 최종 수정일: 2026-10-03. Q1~Q32와 이후 명세 수정 요청을 반영한 설계 기록이다. 최종 명세 검토안은 SPEC.md에 정리했으며 구현은 아직 시작하지 않았다.

## 목적과 결과물

- 우선 목표는 작업 일정의 빠른 등록·수정이다. 코멘트 보관과 조회는 보조 기능이다.
- 최종 결과물은 실행 가능한 Mac 앱과 사내 연결을 대신하는 모의 연동이다. 첫 버전은 emux와 에이전트를 사용하지 않는다.
- 사내에서만 가능한 실제 Jira 연결은 교체할 지점과 주석을 제공한다. 구체적인 API 계약은 아직 확보되지 않았다.

## 확정 사항

### 저장과 역할

- 작업·코멘트는 로컬에 저장한다. DB 외부 저장·동기화, 기기 간 공유는 제공하지 않는다.
- 사내 emux에 필요한 데이터를 보내는 것은 허용되지만, 첫 버전에서는 호출하지 않는다.
- 등록·일정 수정은 폼으로만 처리하며, 제목은 입력한 그대로 저장한다. emux를 이용한 제목 요약·등록·일정 수정은 제외한다.
- Mac 앱이 로컬 데이터 접근과 사용자 확인, 로컬 저장을 담당한다. 폼의 저장 버튼을 최종 확인으로 삼는다.
- 사용자는 사내 노트북에서 Jira 직접 호출이 동작하며 emux의 Jira MCP 토큰과 같은 토큰을 사용할 수 있음을 확인했다. 이번 구현에서는 회사 환경의 실제 호출 계약에 맞춰 교체할 연결 지점을 제공한다.
- 첫 버전은 로컬 키워드 검색만 제공한다. emux와 자연어 검색은 제외한다.

### 작업과 날짜

- 작업은 제목, 시작일, 종료일, 선택적인 Jira 티켓 번호를 가진다.
- 티켓이 없어도 등록 가능하며, Jira 티켓 생성은 하지 않는다.
- 같은 티켓 번호로 중복 등록하면 기존 작업을 보여주고 수정 여부를 묻는다.
- 티켓이 없어도 동일 제목 작업은 중복 등록할 수 없다. 수정도 다른 작업과 제목이 중복되면 막는다.
- 하나의 달력에서 시작일과 종료일을 함께 선택한다. 제목과 티켓은 문자열 입력이다.
- 시작일·종료일을 모두 입력해야 저장할 수 있으며, 종료일은 시작일보다 빠를 수 없다.
- 종료일 선택 시 시작일 이전 날짜를 비활성화하고, 시작일 변경으로 기존 종료일이 잘못되면 종료일 선택을 해제한다. 미완성 기간은 저장할 수 없다.
- 기존 자연어 날짜 생략·연도 추론 정책은 폼 전환으로 첫 버전에서 적용하지 않는다.
- 날짜 기준은 한국 시간이다.
- 상태 표시는 ToDo, InProgress, Closed로 통일한다. 시작일 이전은 ToDo, 시작일~종료일 당일은 InProgress, 종료일 다음 날부터 Closed이다.
- 종료일 연장은 기존 시작일을 유지하고 상태를 다시 계산한다.
- 수동 상태 변경은 직접 허용하지 않는다. 종료일을 오늘로 바꾸더라도 오늘은 InProgress이고 내일부터 Closed이며, 이를 사용자에게 안내한다.
- 앱 실행 중 날짜 변경과 재실행 시 현재 날짜에 맞게 상태를 갱신한다. 자동 상태 변경도 Jira 반영 대상이다.

### 확인과 검색

- 등록·수정은 폼으로만 처리하며 저장 버튼을 최종 확인으로 삼는다.
- 완료된 작업도 검색한다. 후보가 여러 개면 제목·기간·티켓을 보여주고 선택받는다.
- 화면의 작업 목록·상세 조회는 로컬에서 즉시 보여준다. 날짜 직접 수정도 제공한다.
- 제목·티켓·코멘트 원문을 로컬에서 키워드로 검색한다.

### 코멘트

- 코멘트는 요약 대신 원문을 로컬에 저장하고, 동일한 원문을 연결된 Jira 티켓에 추가하는 방향으로 전환했다. 링크와 기록 시각도 보존한다.
- 사용자가 실제 전달받은 시각을 알려주지 않았다면, 조회 답변에서는 앱에 기록된 시각이라고 표현한다.
- 대화 이력과 별도의 변경 이력은 보존하지 않는다.
- Jira 반영을 재개하기 위한 미처리 요청·실패 정보는 대화 이력과 별개다. 처리 완료 후 보존 정책은 구현 단계에서 정해야 한다.

### Jira 반영

- 연결 티켓의 시작일·종료일·상태·코멘트를 로컬에서 Jira 방향으로 반영한다.
- 사용자 등록·수정·코멘트 추가는 로컬 저장 후 Jira 응답을 기다리고, 같은 화면에 성공·실패와 재시도를 표시한다. 별도 시스템 알림은 제외한다.
- 반영 실패 시 로컬 변경은 유지한다. 매일 자동 상태 변경은 백그라운드에서 실행하며 실패는 앱 상세에서 확인한다.
- 창을 닫아도 메뉴바 앱은 계속 실행한다. 완전 종료 후에는 다음 실행 때 미처리 요청을 재개한다.
- 같은 작업의 요청 순서를 보장한다. 아직 전송하지 않은 일정·상태 변경은 최신 값으로 합치고, 코멘트는 각각 보존한다.
- 로컬 삭제를 제공한다. Jira 티켓은 API로 삭제하지 않고 사용자가 직접 처리하도록 안내한다.

### 화면과 제외 범위

- 메뉴바 팝오버는 InProgress 기본 탭과 ToDo·Closed 탭을 제공한다.
- 전체 작업 조회·폼 입력·상세·검색은 앱 창에서 한다. 채팅은 첫 버전에서 제외한다.
- 첫 버전의 캘린더 일정 화면은 제외한다.
- Jira에서 로컬로 가져오기, Jira 티켓 생성·삭제, 대화 이력, 별도 변경 이력은 제외한다.

## 최신 변경과 남은 결정

등록·수정의 폼 전환은 확정됐다. 입력용 날짜 범위 선택기는 제외한 작업 일정 캘린더 화면과 별개다. 코멘트 원문 반영과 Jira 직접 호출, 로컬 키워드 검색으로 첫 버전의 emux 의존을 모두 제거했다.

Q32에서 로컬 키워드 검색이 확정됐다. Jira 직접 호출도 사용자가 사내에서 확인했으므로 첫 버전에 emux는 필요 없다. 회사 API의 구체적인 호출 계약과 필드·상태 전환 대응은 실제 연결 시 확인한다. 이번 구현에서는 교체 가능한 모의 연동으로 둔다.

기존에 합의한 Jira 방향은 로컬에서 Jira로의 반영이다. 원문 코멘트를 동일하게 추가한다는 표현을 Jira에서 변경된 내용을 로컬로 가져오는 양방향 동기화로 확대하지 않는다.

## 디자인 피드백 반영 — 2026-10-03

- 목록 + 상세 구성을 기준으로 제목의 크기·굵기를 높이고 티켓 옆에 작은 말풍선 아이콘과 코멘트 개수를 표시한다. 상세에서는 제목 옆에 둔다.
- InProgress를 기본 탭으로 사용하고 전체 탭은 제거한다. ToDo와 Closed는 각각의 탭에서 조회한다.
- 상태는 차분한 파랑·황토색·녹색 점으로 구분하며, 배경과 텍스트는 기존 중성 톤을 유지한다.
- 작업 기간과 오늘 날짜에 연도를 표시하고, 티켓은 추후 실제 Jira 주소를 연결할 수 있는 독립 링크로 만든다.
- 상세의 티켓·상태·기간은 같은 수준의 정보로 묶는다. 제목 옆 편집 아이콘에서 제목·티켓·기간을 함께 수정한다.
- 기존 명세의 티켓 변경 제외 결정을 이번 요청으로 대체한다. 변경 후의 반영 대상만 바꾸고 이전 Jira 내용은 되돌리지 않으며 과거 코멘트도 새 티켓에 자동 복제하지 않는다.
- 시안의 티켓 링크는 현재 연결 안내만 제공한다. 실제 회사 URL과 Jira 호출은 미연동이다.

### 추가 디자인 피드백 — 2026-10-03

- 목록은 제목 / 티켓·코멘트 개수 / 기간의 세 줄 순서로 변경한다. 목록 말풍선은 더 작게 표시한다.
- 상세에는 별도 본문이 없으며 날짜가 붙은 메모들이 바로 이어진다. 메모 글자와 연한 배경으로 가독성을 높이고 중복 섹션 라벨을 제거한다.
- 등록 시각은 `yyyy/MM/dd HH:mm`으로 표시한다.
- 새 작업·수정 저장 시 유효한 폼을 닫고 Jira 결과는 상세에서 확인한다. 검증 실패 시 폼은 유지한다.
- 클릭 가능한 요소에 포인터 커서를 적용한다.

- 상태 점의 구분을 높이도록 채도를 조금 올렸다. InProgress `#4F89BC`, ToDo `#BD913D`, Closed `#579578`을 목록 필터·상세·메뉴바 팝오버에 공통 적용한다.

### 팝오버 확장과 이름 탐색 — 2026-10-03

- 상단 우측 날짜를 앱 열기 CTA로 대체하고 푸터를 제거한다.
- 앱과 같은 상태 탭을 팝오버에도 제공한다.
- 제목 오른쪽에 수정 아이콘을 배치한다. 클릭하면 해당 작업의 앱 수정 폼을 연다.
- Clerk와 Questlet 아이콘 컨셉을 탐색한다. 이 단계에서는 이름을 검토했으며, 아래 결정에서 Questlet으로 확정했다.

### 이름 확정과 아이콘 방향 — 2026-10-03

- 앱 이름은 Questlet(퀘스트렛)으로 확정한다. 기존 프로젝트 디렉터리 `dayline`은 당분간 유지한다.
- 책·노트와 책갈피의 친근한 컨셉은 유지하면서 노트 + 연필, 노트 + 체크박스 두 안을 비교한다.
- 노트는 흰색·회색으로 두고 연필이나 체크에만 작은 색 포인트를 사용한다. 쿠팡의 여러 원색을 함께 쓰는 방향은 제외한다.
- 앱 콘텐츠 상단 좌측에 작은 앱 아이콘을 배치한다. 약 24px 크기를 기준으로 과한 색·질감 없이 기존의 연한 중성 톤과 조화시킨다. 구체 아이콘은 선택 후 반영한다.
- 메뉴바는 같은 형태를 단순화한 단색 템플릿 이미지를 사용한다.

### 아이콘 스타일 수정 — 2026-10-03

- 사용자가 입체 아이콘을 명시적으로 제외했다. 향후 최종 아이콘은 완전한 2D, 단색 면, 둥근 외곽선의 귀여운 픽토그램으로 만든다. 질감·입체감·그림자·그라데이션은 제외한다.
- 사용자가 빨간 네모로 표시한 레퍼런스를 스타일 기준으로 삼으며 특정 원본 아이콘을 복제하지 않는다.
- 노트 + 연필 / 노트 + 체크박스 두 평면 컨셉을 생성했다. 최종 선택은 아직 미정이다. 앱 안에서는 작은 크기에 맞춰 세부 요소를 줄인다.

- 2D 노트 + 연필 아이콘을 선택해 앱 콘텐츠 상단 좌측의 작업 제목 옆에 34px 영역으로 미리 적용했다. 이미지 여백을 포함한 크기이며 최종 표시 크기는 검토 중이다.

### 화면 표기 변경 — 2026-10-03

- 앱 콘텐츠 상단 좌측 제목은 아이콘과 함께 `Questlet`으로 표시한다.
- 앱·팝오버 탭, 상세 상태, 폼 안내의 사용자 표기는 `진행 중`, `예정`, `완료`로 통일한다. 기존 영문 화면 표기 결정을 대체한다.
- 내부 상태 값은 `InProgress`, `ToDo`, `Closed`를 유지하며 각각 `진행 중`, `예정`, `완료`로 표시한다. 날짜에 따른 상태 계산은 동일하다.

### 브랜드와 등록 버튼 — 2026-10-03

- 새 작업 버튼과 팝오버 + 버튼은 연필의 파란 계열을 유지하되 밝기·채도를 낮춘 `#56729A`를 공통 사용한다. 글자와 +는 흰색, hover는 `#486386`이다.
- 팝오버 앱 이름 왼쪽에 동일한 노트 + 연필 아이콘을 표시한다. 앱 열기 우측에는 + 버튼을 배치하고, 클릭 시 앱을 열어 새 작업 폼을 표시한다.
- 아이콘과 이름 간격은 앱 4px, 팝오버 3px로 줄인다.

### 팝오버 크기 균형 — 2026-10-03

- 상태 탭 12px를 유지하고 작업 제목 12px, 티켓·개수·기간 11px, 행 여백 8px로 줄인다. 제목은 굵기로 구분한다.
- 브랜드 아이콘 영역은 32px, 앱 이름은 15px로 조금 키운다.
- 상단 앱 열기와 +는 28px 정사각 버튼, 내부 아이콘은 14px로 줄인다. 앱 열기는 텍스트와 화살표 대신 `app-window` 창 아이콘을 사용한다. 접근성 이름과 툴팁은 앱 열기로 유지한다. 링크용 화살표와 의미를 구분한다.
- 티켓번호와 링크 아이콘 간격은 2px로 좁힌다. 팝오버 행의 수정용 연필 아이콘은 18px, 클릭 영역은 24px로 맞춘다.

### 디자인 최종 확정 — 2026-10-03

- 사용자가 현재 디자인을 승인했다. 목록 + 상세 구성을 구현 기준으로 확정하고 단일 목록은 비교 기록으로 남긴다.
- 확정된 UI 동작과 표시 규칙을 SPEC 본문에 통합했다. 과거 기록의 영문 표시, 진행 중만 표시하는 팝오버, 팝오버 날짜, 아이콘 미정 표기는 최종 명세로 대체한다.
- 팝오버 수정 연필은 18pt, 버튼 영역은 24pt이며 티켓 링크 간격은 2pt다. 아이콘은 선택한 평면 노트 + 연필이다.

### 생성 기능 추가 — 2026-10-03

- + 새 작업을 +로 바꾸고 앱·팝오버 모두 새 작업·SRD 생성·RP 생성 탭이 있는 생성 폼으로 연결한다. 기본은 새 작업이다.
- SRD는 PRD·제목·상위 페이지 링크 문자열을 받는다. RP는 확장 가능한 role 목록의 검색 가능한 다중 chip 선택과 PRD 링크를 받는다.
- SRD·RP는 생성 CTA로 요청하고 약 10초 모의 API 응답 후 위키 링크를 같은 폼에 표시한다. 작업 목록과 DB에는 등록하지 않는다.
- 실제 API 연결은 이후 사내 계약 확보 후 진행한다. 현재 추가한 것은 명세와 동작하는 웹 시안이며 네이티브 구현은 아직 시작하지 않았다.

### role 후보 목록 확장 — 2026-10-03

- 초기 네 옵션은 향후 늘릴 수 있으며 선택 개수를 네 개로 제한하지 않는다. 후보 목록은 최대 3.5행까지만 표시하고 초과 항목은 세로 스크롤한다. 키보드로 이동한 후보도 자동 스크롤해 표시한다.

### 클릭 영역과 생성 탭 정렬 — 2026-10-03

- 생성 탭 텍스트는 가운데 정렬한다. 앱·팝오버 목록의 작업 선택 영역은 행 전체다. 티켓번호와 링크 아이콘은 하나의 독립 링크 영역이며 수정 아이콘도 행 선택과 분리한다.

### 사내 연동 interface 정리 — 2026-10-03

- codebase-design 스킬로 JiraTicketModule·SRDGenerationModule·RPGenerationModule의 입력·출력·오류·호출 순서를 정리했다. INTEGRATION-INTERFACES.md가 계약, INTEGRATION-GUIDE.md가 mock 교체 가이드다.
